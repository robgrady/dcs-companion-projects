Patch watch · DCS 2.9.30.28536

The September 30, 2026 changelog fixed dynamic-radio numbering and status logic, and explicitly asked pilots to verify VoiceChat hotkeys. This desk treats bindings as a fresh gate, not an inherited assumption.

Stage 01

Declare the route

Choose what the server and flight actually use. Dual stack is valid only when transmit controls are separated to prevent accidental double transmission.

Stage 02

Lock the audio path

Record explicit devices. “Default” is convenient, but a Windows or headset change can silently reroute DCS or SRS.

Stage 03

Prove the controls

Bind by function, then test for collisions. Aircraft-specific VoIP commands can take priority over generic radio VoIP commands.

Stage 04

Set the cockpit

A healthy software path still fails when the aircraft radio is off, tuned elsewhere, volume is down, or the wrong radio is selected.

Stage 05

Run a two-way proof

Use a real partner or server response. Log each leg separately so “I heard a click” cannot be mistaken for complete communications.
